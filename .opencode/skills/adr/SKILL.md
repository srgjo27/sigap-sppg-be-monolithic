# ADR workflow

Use an ADR when a choice affects architecture, public contracts, data ownership, integration strategy, or operational behavior and is likely to matter later.

Required sections:
- Context
- Decision
- Alternatives considered
- Consequences
- Status

Keep the ADR factual and tied to the repository's actual constraints.
