# ADR-0002: MVP-001 Authentication & Role Implementation

- Status: accepted
- Date: 2026-10-05

## Context

MVP-001 (`docs/product/mvp-001-authentication-role.md`) requires login,
role-based access, and activity logs across 8 endpoints under `/api/v1`.
Only MVP-001.1 (create user) and MVP-001.2 (login) are fully detailed in the
spec file; MVP-001.3-001.8 exist as summary rows plus general rules.
The database (`db/schema.sql`) already contains `users` (with `gagal_login`,
`terkunci_sampai`, `wajib_ganti_password`), `audit_log`, and `refresh_token`.
The codebase starts from health-only Gin with no auth, DB, or JWT code.

## Decision

Implement `internal/modules/auth` as a module-oriented vertical slice:

- `domain/`: `Role`, `User` + validation (nama 2-120, email lowercase,
  Indonesian phone, password >=8 letters+numbers), lockout counters
  (5 fails -> 15 min), refresh token generation (256-bit + SHA-256 hash),
  audit filter.
- `application/`: `Service` with ports (`UserRepository`,
  `RefreshTokenRepository`, `AuditRepository`, `SPPGChecker`,
  `SekolahChecker`, `TokenIssuer`, `PasswordHasher`). Scope rules enforced in
  service (kepala_sppg same-SPPG only, no admin/pengawas management),
  not only in middleware, so unit tests cover policy.
- `infrastructure/`: bcrypt (`golang.org/x/crypto`, cost 12 default),
  HS256 JWT (`github.com/golang-jwt/jwt/v5`, 15 min, claims
  sub/role/sppg_id/sekolah_id), Postgres via `github.com/jackc/pgx/v5`,
  plus in-memory stores for tests/dev when `DATABASE_URL` is empty.
- `transport/http/`: DTOs, handlers, `Authenticate` + `RequireRoles` +
  in-memory login rate limit (10/min/IP), stable error envelope
  `{"error":{"code","message","fields?","terkunci_sampai?"}}`.
- `internal/server`: mounts `/api/v1` auth routes; `cmd/api/main.go` wires
  Postgres when `DATABASE_URL` is set, otherwise in-memory (dev only).

Assumptions for underspecified endpoints (001.3-001.8):

- Refresh rotates on each use; logout revokes the presented token (idempotent).
- `GET /auth/me` returns user + `permissions` derived from role matrix.
- `PATCH /users/:id` revokes sessions on deactivate or role/scope change.
- `PUT /auth/password` requires old password, clears `wajib_ganti_password`,
  revokes all refresh tokens.
- `GET /audit-logs` paginates (`page`, `per_page`, max 100) with optional
  `aksi/tabel/user_id` filters; non-admin callers must have `sppg_id` and see
  only their SPPG's actor logs; anonymous failed logins are admin-visible only.

## Alternatives considered

- RS256 / session store: deferred; HS256 is smallest coherent JWT meeting spec
  (`HS256 or RS256`).
- argon2id: deferred; bcrypt cost>=12 satisfies spec (`argon2id or bcrypt`)
  and reuses `x/crypto` already in the module graph.
- `database/sql` + `lib/pq`: rejected in favor of `pgx/v5` for context-native
  pooling and `inet`/`jsonb` handling matching existing schema types.

## Consequences

- New direct dependencies: `golang-jwt/jwt/v5` (JWT), `pgx/v5` (Postgres);
  `x/crypto` promoted to direct (bcrypt). No migration needed; schema already
  contains MVP-001 columns/tables.
- Rate limiting is in-memory per instance; distribute via Redis only when a
  multi-instance requirement appears.
- Audit scoping joins via `users.sppg_id`; future modules reuse
  `Authenticate` + `RequireRoles` middleware for MVP-001.8.
